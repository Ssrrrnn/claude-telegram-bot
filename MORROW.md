# Morrow runtime

Production uses `python morrow_runtime.py`. This entry point sets `MORROW_ONLY=1` before importing the existing persona, memory, voice and continuity pipeline. It binds the owner-only iOS API, runs autonomous activities and writes proactive replies directly into PostgreSQL shared history. It does not initialize Telegram polling or a QQ connection. The old owner ID is retained as the database identity. `/health` is the Railway healthcheck.

Evening private diaries and little notes are generated from dated conversation and completed activity evidence. Missing entries from the last three days are repaired individually; dates without evidence remain empty. A daily receipt, diary, shared note and optional exact user quotation are committed in one transaction. Failures can retry; no public Space posting occurs. The existing diary-disable command remains effective after redeploy.

The read-only web MCP is available at `POST /mcp` with the same owner bearer authentication. It supports stateless JSON responses, stable 2025 protocol negotiation, initialization notifications, ping, tool listing and calls. Unexpected browser Origins are rejected. The tools read public HTTPS pages, browser receipts, voluntary listening context and voluntary health summaries. Public DNS addresses are pinned by the connector resolver; redirects are checked again; page types and sizes are bounded. Page text is untrusted data, not executable instructions. No browser JavaScript, account login or external writes are supported.

Client additions use `GET /v1/browsing` and `GET/POST /v1/context/{listening|health}`. Sending JSON `null` clears the corresponding server context. Health fields are limited to steps, sleep hours and an explicit source; snapshots carry a server reception time. The client shares its actual playback state while foregrounded. Reading that state does not mean a second device is playing in sync.

The free AltStore iOS build supports local notifications, audio playback and Now Playing controls. It does not have APNs or HealthKit entitlements. Closed-app server push requires a separately provisioned Apple push capability and provider credentials. Direct HealthKit access requires a supporting signed build and the user's on-device authorization. The existing build offers voluntary manual health summaries. QQ and NetEase song links open the provider; full catalog streams require authorized provider integration.
